# 2026-10-21 マナコイン・XP の増殖対策 と Web ログイン（auth/argument-error）の修正

## ① マナコイン・XP が同期のたびに増える件

### 原因（再現できたもの）
`userDataSyncCore.ts` の 3-way マージ（`mergeCounter = base + (local − base) + (remote − base)`）そのものは正しい。
問題は **base（前回そろえた値）の保存のタイミング**。以前の順番は

1. クラウドを読む → 2. 合わせて端末へ書く → 3. 送る → 4. 届いたら base を保存

- **3 は届いたのに 4 の前にアプリが閉じられる**（スマホで裏に回した直後に OS が終了させる、など）と base が古いまま残る。
  次の同期では local と remote が同じ値でも `110 + 110 − 100 = 120` のように、この端末で増えた分をもう一度足す。
  base が古いままなので **同期のたびに倍々で増える**（シミュレーションで 110 → 120 → 140 → 180 → 260）。
- **3 が失敗**すると、端末には合わせた値が入っているのに base は古いまま。ほかの端末で増えた分を二重に足す。
- **XP も同じ式で増えるので、レベルも上がっていく**（XP 1200 → 1400 → 1800 → 2600 → 4200 → 7400、Lv6 → 7 → 8 → 10 → 13 → 19）。学習時間・単元の回数も同じ仕組み。
- アプリ版だけでも起こる（Web と行き来しなくても、裏に回すたびの同期で起こりうる）。

### 直したこと（`src/utils/userDataSyncCore.ts` / `src/utils/userDataSync.ts`）
1. **端末とクラウドが同じ値なら、base に関係なく何もしない**（古い base が残っていても二重に足さない）。
2. **送る前に「送っている途中」の状態を保存**（送る値・送る前のクラウドの値）。次の同期で
   - クラウド＝送った値 → 届いていた（base＝送った値）
   - クラウド＝送る前の値 → 届いていない（base＝送る前のクラウドの値。端末はもう取り込み済み）
   - どちらでもない → base を使わず「大きい方」（二重に足さない・減らさない）
3. **Firestore のキャッシュ（オフライン）の古い値では合わせない**。
4. **同じ端末の別タブと同時に走らない**（Web Locks）。

### 既存ユーザーへの影響
- **コイン・XP は消さない・減らさない**。今の値はそのまま残る（すでに増えてしまった分を自動で減らすことはしない）。
- 保存形式は `user_data_sync_base_v1_<uid>` のまま中身に `v:2` を足しただけ。古い形式もそのまま読める（読み替えのテストあり）。
- Firestore のルール・フィールドは変えていない（ルールのデプロイ不要）。
- 1回目の同期は今までと同じ結果（前回の base をそのまま使う）。

### テスト
`tests/userDataSyncNoDoubleCount.test.ts`：レベル（XP）／学習時間／2台を何度も行き来／送信後に閉じられる／送信失敗／送る前に閉じられる／ガチャで減らす／古い形式の読み替え。

## ② Web 版で「Firebase: Error (auth/argument-error)」でログインできない件

### 原因
1.0.2（10/16）でアプリ版のログイン保存のために `firebase.ts` を `getAuth` → `initializeAuth(app, { persistence })` に変えた。
`initializeAuth` には **popup / redirect の部品（`popupRedirectResolver`）が入らない**ので、
Web の `signInWithPopup` が `auth/argument-error` で失敗するようになっていた。アプリ版はネイティブのログイン（`signInWithCredential`）なので影響が出ていなかった。

### 直したこと（`src/utils/googleAuth.ts` だけ）
- `signInWithPopup` / `signInWithRedirect` / `getRedirectResult` に `browserPopupRedirectResolver` を **呼び出しごとに渡す**。
- `firebase.ts`（アプリ版のログイン保存の設定）は **変えていない**＝アプリ版の挙動は変わらない。
- アプリ版ではリダイレクトの結果受け取りもしない（今までも結果は無かった）。
- まだ argument-error が出たときは「ページを再読み込みして…」と案内する文に。

### 確認
- 開発サーバーのブラウザで `browserPopupRedirectResolver` が読み込めること・画面にエラーが出ないことを確認。
- 本番の Google ログイン画面（ポップアップ）は、デプロイ後に Web 版で一度ログインして確認してください。
